Framework Placement Bench

Twelve pieces of game state, six classes to put them in. The tree on the left fills in as you choose. Then every placement gets run through five situations at once — because the one situation almost everybody tests in is the one that hides the mistake.

Where you put things

Runtime ownership, not inheritance. Indentation means “is created and owned by”.

server only — the pointer is null on every client.

local only — exists on the server and on that one player's machine, nowhere else.

replicated — every machine has a copy of every player's.

dies and respawns — destroyed the moment the player is killed.

Place each piece of state

It opens pre-filled with a mix of correct answers and the mistakes people actually ship. Change what you disagree with, then run the checks.

The rule behind all twelve. Ask two questions in order. How long must this outlive its owner? — that picks the depth in the tree. Who is allowed to read it? — that picks between the classes at that depth.

Score on the Pawn passes every test until somebody dies. Match state read straight off the GameMode passes every test until a real client connects. Settings on the GameMode pass every test until you call OpenLevel. None of those are subtle bugs — they are just invisible to the one arrangement you happen to be testing in.
