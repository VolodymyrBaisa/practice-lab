Punch Bench

Press simulate and watch two arrows. The teal one is how far the bat has moved from where it started. The amber one is how fast it is going right now — and it flips around when the punch turns into a return.

start — a place bat — a place offset — a move velocity — a move per second

CurvePunch — alpha across, curve value up. Drag the middle key to reshape the punch. The outer two are pinned at zero, the way the asset is.

One number into the next

Each row names the variables it is built from, then shows the same sum with this frame's numbers. The highlighted value is always the answer from the line above.

  1. Elapsed PunchElapsed + DeltaTime
  2. Alpha PunchElapsed / PunchDuration
  3. Curve CurvePunch->GetFloatValue( Alpha )
  4. Offset curve value × PunchDistance
  5. Step TargetBatDirection × Offset
  6. Desired PunchStartLocation + Step
  7. Gap Desired − component location
  8. Velocity Gap / DeltaTime

A place

Where something is. Its length means nothing on its own.

A move

How far and which way, with no starting point of its own.

A velocity

A move divided by seconds. The only one physics can use.

The same five lines

The first four rows above are plain numbers. The vector appears only when the direction is multiplied in, and the last line turns it into something the solver can act on.

PunchElapsed += DeltaTime;
float Alpha    = PunchElapsed / PunchDuration;
float Offset   = CurvePunch->GetFloatValue(Alpha) * PunchDistance;
FVector Desired  = PunchStartLocation + TargetBatDirection * Offset;
FVector Velocity = (Desired - Component->GetComponentLocation()) / DeltaTime;

Desired is a place, so handing it to SetRelativeLocation says be there now — the bat appears at each amber-free position having travelled through nothing, and pushes nothing. Dividing by DeltaTime turns the same information into the amber arrow, and SetPhysicsLinearVelocity makes the solver travel that arrow, which is what finds the puck.
